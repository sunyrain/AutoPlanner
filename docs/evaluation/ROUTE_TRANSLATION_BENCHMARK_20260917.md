# 路线中文展示层：Luna / Terra 实测（2026-09-17）

## 结论

今天面向专家的交流资料使用 **GPT-5.6 Terra / low**，并配合项目术语表。Luna / low 可作为后续低成本候选，但本次出现了将化学意义的 reduce 翻成“降低”的问题，暂不建议不经术语校正直接对外展示。提高 reasoning effort 不是翻译质量的稳定改进手段。

这只是 10 条真实文本、每种配置 2 次的现场抽样，不是化学翻译能力榜单，也不是实验有效性评估。

## 方法与边界

- 来源：`results/discussion/statin-serial-20260917` 的真实策略、关键假设、审查重点、反应描述、长条件和审查意见。
- 输入固定：10 条、2,771 个英文字符；覆盖立体化学、单位、否定、操作顺序、GDH 的辅因子再生职责，以及酶筛选尚未解决的依赖。
- 配置：Luna / Terra × low / medium / high × 2，固定随机顺序、串行运行，共 12 次。没有测试 none、xhigh、max。
- 通道：Codex CLI 0.145.0，已有 ChatGPT 登录，HTTPS；隔离临时目录、只读、关闭搜索和工具；严格 JSON 输出。
- 计时口径：启动 CLI 到完整 JSON 返回的墙钟时间，含客户端启动、网络和服务端生成，**不是纯推理时间，也不是首 token 延迟**。
- 相同用户载荷不代表相同模型内部输入：CLI 的模型指令开销不同，且少量 Terra 请求命中缓存。没有强行绕过缓存，也没有把实测差异归因于单一推理参数。

## 逐项检查发现

1. **数字检查不是语义检查。** Luna low-2 将 “Reduce … the C36 ketone” 译为“降低……C36 酮基”；Luna medium 两次也有同类用词。数字和构型仍全部保留，因此简单的格式校验发现不了这个错误。Terra 六份译文均使用“还原”。
2. **项目词汇需要定义。** “bound stock” 在 Luna medium-1 中被译成“有库存的结合物”，Terra 多次译成“受限库存”，Terra high-1 则译成“结合库存”。高档位也不能自行知道这里是软件绑定的库存目录。生产术语表明确为“本任务绑定的库存”。
3. **提高档位未消除表述问题。** Luna medium-1 出现“后续 C 部分 Cbz 氢解”，medium-2 在 Cbz 中插入不可见字符。Luna high 更慢，句子总体仍与 low 相近。
4. **酶的不确定性保留较好。** 12 份均保留具体底物、C11-S / C8-R、C6=C7 E 构型、酶/辅因子用量尚需筛选，并明确 GDH 仅用于再生；没有把待筛选酶写成已验证催化剂。
5. **操作先后与否定保留较好。** 12 份均保留“先去除过氧化物与淬灭残留物，再接触 Pd/C 或氢气”的限制，以及 E 异构体富集未经验证的限定。
6. **格式警报要解释。** Luna high-2 将原文拼写的 two-carbon 改为“2碳”，触发阿拉伯数字新增检查；这里是数字表现形式改变，不能当成碳数或化学错误。其余 11 份通过当时的数字/核心缩写检查。
7. **两模型都偏直译。** “精确游离酸”“筛选依赖项”“取代信息已编码”等并不够自然。生产词表统一常见项目与化学用语，但翻译不能自行修订原始路线结论。

- 翻译字段含策略、后续策略调整、关键假设、审查重点、反应与条件、限制和审查理由。
- 分子 SVG、SMILES、原子映射、步骤身份、连接关系、操作及 verdict/status 不翻译、不改写；中文版不向求解器回写。

运行工具：`scripts/translate_route_exports.py`。批量输出与英文快照：`results/discussion/route-zh-20260917/`。完成后的入口为该目录的 `index.html`，每个任务附路线图、策略/完整条件中英对照、英文原版。

## 批处理提速与恢复

原始批量设置是每请求最多 10,000 英文字符（约 25–50 条），2 路并发，并非每条单独请求；但此设置对本次资料量过于保守。正常批次多耗时 65–83 秒，重复 CLI 启动及通用上下文开销较多。

按用户要求改为可配置的大批量并行，默认 **8 路并发、每请求 45,000 英文字符**（本次大批次约 180–210 条），每请求时限 600 秒。允许配置 1–32 路并发；32 是本工具防误配置的本地上限，不代表服务商并发限额。并行越多并不保证线性加速，应结合账号实际限流、长输出稳定性和网络情况调整。

恢复时已有 998 条文本可复用；先用 10 条缺失文本验证真实通道，29.368 秒完成、无重连，随后将剩余 **1,409 条 / 322,471 英文字符拆为 8 个请求同时执行**。通道探针是生产资料的一部分，其输出直接复用，不重复翻译。失败/中断尝试保留，后续只对缺失源文本创建新尝试目录。

| 边界或故障 | 分类 | 依据 | 处理与验证 |
|---|---|---|---|
| 单次 HTTPS/TLS 或流中断 | K1 / 运行期丢失 | 第 25、26 批无输出；第 27、28 批重连后取得完整输出 | 只保留/复用完整输出；连接探针成功后恢复缺失项，不重跑整个任务 |
| 原始数字、构型、结构与审查结论 | K0 / 展示正确性 | 曾漏掉 1.5 当量及一个 C5 位点；也存在纯数字书写形式差异 | 核对源文后在独立校订表修正，保留原始模型输出；输出覆盖和科学数据一致性检查仍保留 |
| 旧批号决定是否完成 | K3 / 恢复范围过大 | 批次大小改变后，旧批号不能代表哪些文本已完成 | 改为直接读取已有完整输出的源文本 ID；并发与断点复用有针对性测试 |

批量设置改变不影响前面的 12 次速度对照记录。中文数据独立于求解器，网站与逆合成任务进程未停止或重启。恢复判定为 `resume`；最终发布仍要求完整覆盖。浏览器视觉验收未完成：Computer Use 无法可靠确认当前 URL，已按其要求停止 UI 操作；离线数据与 JavaScript 语法验证不冒充视觉验收。

```powershell
python -X utf8 scripts/translate_route_exports.py translate --model gpt-5.6-terra --effort low --workers 8 --batch-chars 45000 --timeout 600
python -X utf8 scripts/translate_route_exports.py render --model gpt-5.6-terra --effort low
python -X utf8 scripts/translate_route_exports.py verify
```

## 完成结果

- 8 路并发的 1,409 条补全请求 **317.87 秒（约 5 分 18 秒）**全部完成；8 / 8 成功，没有连接重试。7 个大批次分别包含 182–216 条文本，尾批 33 条。时间从第一条模型调用启动到最后一条完成，不含之后的人工式逐项校订和页面渲染。
- 这轮输入 214,280 tokens（其中缓存输入 57,856），输出 118,115 tokens。套用上述 API 单价估算 **$1.74**，不是 ChatGPT 订阅实际账单。没有声称与旧批次做过严格配对的吞吐对照。
- 最终覆盖 **2,417 / 2,417** 去重文本，8 个任务、22 个策略分支、274 条反应记录，另包含 76 次后续策略调整的说明。
- 复核发现 anilide/carboxanilide 被多处译成“苯胺/羧基苯胺”。针对检出的 48 条文本检查后，通过源词限定的术语规则统一为酰苯胺，并修正一处逆合成拆解/正向环化的方向表述。11 条完整句校订及 3 条限定术语/排版规则保存在 `reviewed-corrections.json`；原始模型输出未覆盖。这说明 Terra 也不能免去领域术语控制，不能将格式检查通过等同于化学翻译完全正确。
- 大批量的 7 项自动警报中，3 项为数字书写形式，3 项为 LiOH 被写成氢氧化锂，1 项是 review-014 至 review-011 被温度负号规则误判；分别校订或缩小检查范围，没有删除有效的结构、数值、构型及单位保护。
- 导出 40 个页面：每个任务包含中文/英文路线图、中文/英文结构条件总览、完整策略及条件中英对照。离线验证确认原始科学字段与分子 SVG 不变、内联脚本语法正确、所有分支/记录均在说明页可访问，无无效 SMILES。25 个相关测试通过（未运行 3 个浏览器测试）。**没有完成视觉验收，也没有宣称对全部反应做过独立化学复审。**
- 所有翻译模型请求已结束；未改变本地实时站的求解模型或历史 IO，也没有将翻译强制接入正在运行的任务。
