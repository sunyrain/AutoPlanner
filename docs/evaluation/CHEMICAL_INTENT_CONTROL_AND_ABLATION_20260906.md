# 结构语义、失败恢复与配对试验（2026-09-06）

本轮完成了通用控制修复、实际模型试验及匿名独立模型评审。**能够确认软件路径变得正确、失败反馈开始影响动作；目前不能确认连续 Strategy、checkpoint 或依赖字段一定提高最终路线质量，更不能据此给出天然产物 benchmark 的提升百分比。** 未训练模型，也未引入学习型价值函数或额外控制器。

因此，三个误用控制被移除/收窄：中间立体提前剪枝 1→0、正常反应的无权限参考 ID 拒绝 1→0、事务上下文副本 2→1。最终身份检查保持不变。恢复理由来自模型，Host 只执行合法操作；模型仍可能选错化学方案。

## 2. 试验口径

每个机制选择一个冻结状态，比较开/关两组。不是从目标开始的盲发现试验，也不是三种机制之间的总排名。模型均请求 GPT-6 Astra medium；每组配置 12 个模型调用槽、80 万输入 token、10 万输出 token、30 分钟、8 次 Builder 上限和 2 次 Editor 上限。规划、检索工具回合及内部复审计入同一组，独立评审另计。

| 机制 | 共同输入 | 唯一计划差异 | 排除的混杂 |
|---|---|---|---|
| 连续 Strategy | Homocubane 已有两步前缀，以及历史真实 checkpoint 的有效 uncertain 判断 | 里程碑上限 1 / 2 | 两组均启用 checkpoint；不把“关掉 Critic 后不再推进战略”当作 Strategy 消融 |
| checkpoint | BCH 同一个四步前缀、同一个原始关键闭环候选 | Key Critic 关闭 / 开启 | 两组里程碑上限均为 1；共同候选占一个政策槽，但没有新 provider token |
| 依赖反馈 | 同一个 BCH 七步路线、同一个原始拒绝判断；附加依赖来自已保存的新 Critic IO | 向 Editor 隐藏 / 提供 `chemical_dependencies` | 原有逐步判断及其正文不改变；这只检验依赖投影，不检验新 Critic 的检测能力 |

独立评审只读匿名化结构、反应、条件和操作；不读组别、Strategy、原 Critic、修复过程或原任务 ID。条件沿用规范化字段，包含催化剂、溶剂等，避免匿名化时再次误删有效化学信息。相同化学输入只评审一次，不通过重复评审相同原路线制造组间差异。尚未提交的修复，评分对象仍是原路线；临时工作视图单列。

用户已选择本轮先做独立模型评审，专家随后复核。同一底座的新任务是过程独立，不等于知识独立或实验验证。

**预算限制必须说明：** 配置上限相同，实际花费无需相同；但输入 token 是调用准入预算，末次调用可能超额。连续 Strategy 开启组最终为 823,087，比 800,000 高 23,087；另有 timeout/服务不可用调用缺少完整 usage。因此本轮不是严格 token 匹配的统计效果证据，不能给出显著性或成功率提升。

| 机制/组别 | 新 Worker 尝试¹ | 已知输入 token | 输出 token | 最终保留结构 | 匿名独立模型评审 |
|---|---:|---:|---:|---|---|
| 连续 Strategy 关 | 8 | 468,211 | 6,403 | 8 步，库存未闭合 | uncertain |
| 连续 Strategy 开 | 12 | 823,087 | 8,502 | 8 步，库存未闭合 | uncertain |
| 依赖反馈关，单事务版本 | 5 | 454,750 | 5,400 | 原 7 步；修复复审拒绝，回滚 | uncertain |
| 依赖反馈开，单事务版本 | 5 | 407,375 | 4,071 | 同一个原 7 步；修复复审拒绝，回滚 | 同一匿名判断 |
| checkpoint 关 | 4 + 1 个共同输入槽 | 401,774 | 4,289 | 8 步，库存未闭合 | reject |
| checkpoint 开 | 7 + 1 个共同输入槽 | ≥626,727² | ≥5,486² | 仅余 4 步前缀 | uncertain，不能视为更好完整路线 |

¹ 统计实际新 Worker 尝试，包括失败/超时，不能与 provider 内部 Responses 次数等同。② 其中一次 Builder 300 秒超时缺少 token 用量，表中是已知下限。

**连续 Strategy：机制触发了，质量增益未证明。** 开启组真实产生了一次新 Strategy、一次 Strategy 审查，以及更多关键事件审查；两组最终都是 8 步、未闭合、独立评审不确定。它增加了战略更新能力，但本例没有证明它更高效或产出更好路线。

**依赖反馈：改善范围选择，不等于完成修复。** 关闭组初次选择闭环和活化两步；开启组加入提供所需醇构型的前一步。两组都通过了结构重建并到达整路复审，这已经不同于上一轮“始终未接回”的 canary；但化学复审均拒绝替换，原路线被保留。47,375 个输入 token 的差额主要来自后续调用波动，不能当作稳定的能力或节省增益。

**checkpoint：早期干预真实发生，但本例没有节省总成本。** 开启组在同一个共享闭环候选上先提出立体疑点，随后走 Editor 修复；关闭组继续展开后才做整路审查。开启组最终没有完成替代路线，且多花了调用并发生超时。

尤其不能用 `reject → uncertain` 宣称质量提升：开启组只剩四步前缀。关闭组独立评审的明确拒绝位点是第一步硼酸酯交换的 C6 构型/所称保留机制，**不是 checkpoint 对闭环步骤的同一发现**；该闭环在独立评审中仍是 uncertain。因此外审未直接证实该次 Key Critic 的化学判断正确。

同一个原始 BCH 七步路线，在规划 Critic 中是 reject，在匿名独立任务中是 uncertain。所有判断均保留；这体现审查上下文与模型判断的敏感性，不能把后一个判断自动当成前者已被纠正。

主配对来源：[连续两组与单事务依赖两组](../../results/discussion/mechanism-pilot-v2-20260906/summary.json)、[修正输入后的 checkpoint 两组](../../results/discussion/mechanism-pilot-v4-20260906/summary.json)。不同控制修订版本分开保存，不把不同版本的开/关组拼成一对。

## 4. 复审失败恢复的追加验证

在发现复审后提前退出的问题并修正后，重新进行了同输入、同预算的依赖两组验证，单列为 v3，不混入上表单事务版本的效果比较。

- 关闭组：第二次 Editor 从两步扩大到三步，第二次重建完成；末次复审遇到服务端容量不足，保留为 `rebuilt_pending_recritic`，不提交候选。9 次新 Worker 尝试，已知 742,848 输入，另一次失败调用 usage 未报告。
- 开启组：两次 Editor、六次 Builder、两次整路复审；第二次替换仍被拒绝，原路线完整保留。10 次尝试，921,959 输入；超过配置输入上限，不能作为严格预算内比较。
- 匿名评审读取原路线，而不是 pending 事务的临时 `branch.steps`；两组因此仍对应同一个七步匿名输入，直接引用同一份已有评审。

这组证明了“失败原因 → 下一次 Editor → 新修复范围/目标 → 重建/再复审”的真实可执行路径，未证明成功的化学修复。来源：[恢复验证](../../results/discussion/mechanism-pilot-v3-20260906/summary.json)。

## 5. 成本归因与无效试验

连续 Strategy 开启组多记录 354,876 输入 token（约 75.8%）；分角色差额为：

| 差额来源 | 输入 token 增量 |
|---|---:|
| 新 Strategy + 其审查 | 110,466 |
| Key Critic | 121,854 |
| Builder | 58,895 |
| 最终 Critic | 63,661 |

不能把全部差额归因于新 Strategy 的几句话。工具回合会重复携带上下文；业务 prompt 字节与 provider 输入 token 是不同测量。缓存输入是输入的子集、推理输出是输出的子集，均不重复加总。本轮不据此估算未确认的人民币/API 费用。

保留但不用于机制效果判断的试验：

| 记录 | 排除原因 | 已知输入 token |
|---|---|---:|
| v1 依赖两组 | `expand` 参考 ID 的过严验证影响正常反应 | 1,588,135 |
| v2 checkpoint 两组 | 历史局部 atom maps 未先统一，前缀重放冲突，Key Critic 实际均未触发 | 1,840,715 |

后者是本轮试验驱动器的输入物化问题：已改用生产流程的全图 rebase + assemble，并在付费执行前验证完整冻结前缀可回放；没有修改原始历史结果。修正后 checkpoint 的真实 Key Critic/Editor 路径已触发。

全部规划运行（主配对、恢复追加验证和上述无效试验）共 **88 次新 Worker 尝试，已知输入至少 8,275,581、输出至少 75,981 token**；另外 4 个共同候选槽不调用 provider。五次匿名独立评审合计输入 284,504、输出 24,445 token。总计 93 次新 Worker 尝试，已知输入至少 **8,560,085**、输出至少 **100,426**；两次失败/超时调用缺少完整用量，不记作免费，也不隐藏无效试验消耗。
