# 给定起始物的路线设计

本设计针对 `起始物 → 目标`，与原有 `目标 → 任意配置库存` 区分。首个案例：

- 目标：`OC[C@](O)(C#C)C=O`，RDKit 确认为 R 构型。
- 方案 A 起始物：`OCC(O)CO`，甘油，C3。
- 方案 B 起始物：`OC(CO)(C#C)CO`，对称炔基三醇，C5。
- “A 或 B”按两个独立任务比较；两者不是同一路线必须同时使用的原料。

## 必须分开的三个问题

1. **物料可得性**：哪些终端物料可以由用户供应或从指定库存获得？
2. **起始物约束**：这条路线是否确实从用户指定的原料出发，沿连通反应贡献目标骨架？
3. **化学质量**：反应、立体控制、兼容性和条件是否可信，哪些仍待证实？

把甘油加入库存只能回答第一项。路线从别的高级中间体购买闭合，或者在条件里写上甘油，都不能回答第二项。
一个满足指定起始物约束的路线可以仍然被化学 Critic 判为 uncertain/reject；这两种评价不得合并。

## 通用接口建议：只增加一个必要输入

建议在 `TargetConstraints` 增加 `required_starting_materials: list[SMILES]`。

- 空列表：沿用现有自由逆合成。
- 一个结构：每条交付路线必须真正使用这个起始物。
- 多个结构：每条交付路线必须使用全部所列起始物，例如指定两个偶联片段。
- 可替代的起始物：像本例一样分别提交任务；第一版不增加 AND/OR 表达式、配方 DSL 或模式字段。
- 按现有结构标准化处理盐、同位素、立体化学和完全指定的身份；不自动把消旋体当作指定单一异构体。
- 用户给定起始物按任务内供应物料处理，来源归属于该任务，不写入全局商业库存。

起始物的量、纯度、供应形态等只有影响路线时才进入已有需求文本。不是必填字段。
一般骨架保留要求也先写在需求文本；本例另外核对甘油 3 个碳、炔基三醇 5 个碳向目标的贡献。
不能用通用的“分子小”“相似度高”或手工优先分数代替起始物可达性。

## 插入位置与职责

| 位置 | 必须做什么 | 不应做什么 |
| --- | --- | --- |
| 请求编译 / `TargetConstraints` | 保存并标准化指定起始结构，绑定任务内供应身份 | 仅藏在 `safety_limits.process_brief` 中并声称已获得硬约束 |
| Strategy | 同时看到目标和指定起始物；考虑骨架来源、必须新形成的键及立体来源 | 先从任意高级库存选短路线，再用一句话声称能从起始物制备 |
| Builder | 保留现有一步 ReactionJSON 输出；沿目标反推并用给定起始物前向检查；沿用 `continuation_hint` | 额外输出完整路线计划、相似度评分或复制起始物字段 |
| Host / 搜索状态 | 从已重放的路线和终端叶子派生尚未满足的起始物；库存命中与起始物满足分开 | 从模型自报“已到达”或仅凭分子在树中出现而判定满足 |
| Critic | 检查从指定原料到目标的化学连续性、立体来源和条件 | 把供应状态当作化学可信度，或代替 Host 核对 exact leaf |
| Editor | 修复后重新检查指定起始物是否仍在保留的连通路线中 | 沿用修复前的满足状态 |
| 收敛与展示 | 并列显示库存闭合、起始物满足、化学评价；明确开放的缺口 | 仅库存闭合就宣布给定起始物任务成功 |

共享任务前缀应只增加简短规则，例如：

> Plan a connected synthesis from every required_starting_material to the exact target.
> These are mandatory backbone-supplying terminal inputs, not optional stock additions.
> Other configured inputs may supply reagents or necessary fragments. Reason backward from
> the target and forward from the supplied starts. The Host checks route connectivity and
> exact starting-material use; evaluate chemical feasibility in the existing fields.

不需要修改 Strategy、Builder、Critic 的输出 schema。Host 可以从已有图计算起始物满足情况，
也不需要每一步新增一个模型自报布尔字段。

## 搜索终止需要实际改动

当前 AiZynthFinder 搜索在所有终端叶子命中库存时把状态视为 solved。
因此只在最终报告增加校验不足以实现通用功能：如果仍未到达指定起始物，搜索必须能继续。

实现时应把“用户供应起始物”作为路线级义务，而不是修改全局库存真值：

- 维护真实库存查询，仍允许普通试剂/新增碳源作为终端。
- 路线达到库存边界但未满足起始物时，不标为任务 solved。
- 将尚未满足的起始物连同当前连通路线提供给现有 Builder，由模型选下一步或重考虑路径；不以分子大小或相似度强选一个可购叶子。
- 用现有候选回退和路线修复处理走到错误原料的分支；不重新运行全部已完成 Strategy。
- 到达 exact 起始物后保留该终端，不继续要求合成用户已提供的物料。
- 不要求单调降低目标与起始物的图距离；保护基、氧化态变化和必要重排可能先增大距离。

最小验证应包括：库存闭合但缺指定起始物不能算成功；真正连通的指定起始物可满足；
旁挂/未反应/仅在条件中的起始物不能满足；错误对映体不能满足；修复删除起始物后状态失效；
不同指定片段的汇聚路线；新功能未启用时现有流程保持原义。

## 本次实验的实现边界

本次先使用现有生产 CLI、独立 Codex 会话、ReactionJSON 重放与 Critic。
指定起始要求通过已有 `process_brief` 传给全部角色；每个任务使用独立的
`94 个常用物料 + 1 个给定起始物` 的精确库存，不混入全 ZINC，以减少在其他高级原料处结束的机会。
运行后另行检查连通路线的 exact 起始叶子和目标碳原子来源。

**这是一项原型实验，尚未把上述 `required_starting_materials`、搜索终止与网页输入全部接入生产系统。**
限制库存不能替代通用路线级义务检查，也会限制其他合理辅助原料的选择。
催化剂、溶剂和非骨架试剂的供应不应因为不在这份小库存就被自动当作化学失败；
模型若混淆这一点，应记录为实验局限，而不是冒称已实现通用固定起始物规划。

本例还显示，条件文本中的辅助试剂不一定成为搜索图的终端叶子。例如甘油的一条候选
用溴乙烷制备格氏试剂，但该辅助试剂不在这份 95 项库存中；另一条候选使用库存内的
溴甲烷。两者都不改变目标炔基的乙炔碳来源。因而“图中终端全部命中库存”不能
扩展解释为全部试剂、酶和辅因子都已落实采购。若用户另外限制辅助试剂供应，
应将它作为明确的物料要求评价，不能偷换成指定骨架起始物要求。
