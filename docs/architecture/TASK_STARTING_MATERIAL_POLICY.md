# 随任务变化的起始物范围（设计草案）

状态：2026-09-17 讨论方案，尚未实现。不修改默认库存、历史结果或现有模型输出格式。

## 1. 定义：目录事实稳定，任务允许的起点变化

库存目录回答某个精确分子是否存在于指定来源中；任务起始物规则回答是否允许从该分子停止向上游追溯。后者取决于目标、任务范围和该分子在路线中的作用，不仅取决于目标 SMILES。

同一个匹伐他汀取代喹啉醛：

| 任务 | 作为起点的处理 |
| --- | --- |
| 研究完整骨架及侧链的合成 | 若规则要求解决喹啉核心构建，则继续拆解，即使目录命中 |
| 从该喹啉醛出发，研究侧链连接 | 明确允许作为指定起点，来源按本任务的供应边界另行处理 |
| 采购导向的最短制备方案 | 来源条件满足且用户允许高级中间体时，可以停止 |

来源条件与任务许可同时满足，才可将一个前体作为终点。给定起点是一项任务假设或要求，本身不是实时采购或已有实物的证明。

固定起始物任务还存在路线级要求：必须有从指定原料到目标的真实物质连接。仅将该原料列为溶剂、试剂，或命中其他通用起点，都不算满足“从 A 出发”。“允许 A”与“必须从 A 出发”不能混同。

## 2. 不按目标复制或重建几千万条库存

保留现有来源索引和精确身份查询，在候选成为终点时按需应用任务规则。一次任务内所有策略共享同一规则，不随分支、搜索深度、预算消耗或暂时困难自行放宽。

规则在任务开始时由用户需求明确；缺少特定要求时使用明确的默认范围，不能擅自要求每个目标重建全部环系或全部手性。仅有目标结构不能唯一推出合理的起始物边界。

开始时确定原则即可，不要求预先枚举所有高级中间体。搜索中逐渐增加的是具体候选的判断结果，不是不断改变规则。

## 3. 最小输入与判断内容

只需要一份任务级起始物规则，必要时附带用户明确给出的结构和允许/禁止/必须使用关系。先不增加复杂度分数、距离分数、供应评分或独立角色说明。

示例规则：

> 本任务研究匹伐他汀完整路线，包括目标取代喹啉骨架及关键手性侧链的构建。允许通用试剂、通用砌块及指定手性源作为起点。不得以已经完成上述研究内容的目标专用高级片段直接闭合路线。明确要求保留的外购片段除外。

这是“完整路线研究”范围的例子，不是所有目标的默认政策。局部改造、半合成或给定起始物任务需要相应范围。

对需要语义判断的具体候选，内部结果只需：

- 决定：允许终止、继续拆解、暂无法判断。
- 一句理由：指出该候选已经包含哪项本任务要求自行完成的工作，或依据哪项明确许可可以终止。

身份、库存来源和当前路线直接引用已有上下文，不让模型重复生成。暂无法判断不代表反应不可行或目录未命中；该候选暂不支持完成声明，其余搜索可以继续。

## 4. 如何执行一次候选判断

1. 取得真实反应参与物和宿主重放结构，查询本任务绑定的来源目录。明确指定的起始物按任务约定的来源条件处理，不虚构供应记录。
2. 对精确禁止结构、明确许可结构以及已有通用试剂清单执行直接判断。用户明确禁用要求优先于通用清单；相互冲突的显式要求不能由模型私自选择。
3. 对命中目录、但是否绕过研究内容尚不清楚的路线前体，给模型目标、固定规则、该候选和相关路线片段，判断它是否提前完成了规定的骨架构建、片段连接或立体化学工作。
4. 允许终止的前体退出待展开集合；要求继续拆解的前体保留在搜索中。原始库存命中事实不变。
5. 汇总完整路线时仍使用相同规则检查终点和必须使用的起点，防止修复、剪枝或重新组合恢复一个本来不允许的终点。

结构相似度、公共子结构、环数、分子量或手性中心数可以提示需要检查的位置，但不能单独决定许可。CBr₄ 约 332 Da，匹伐他汀完整喹啉醛约 291 Da，是分子量阈值会误判的实际例子。

“高级”需要给出与任务有关的具体理由，不能只使用笼统标签；天然产物、手性池分子也可能是合理且明确允许的起点。

## 5. 反应角色、原子映射与缓存

`CO-REACTANT` 是显示角色，不能成为跳过任务判断的开关。CBr₄ 这类通用试剂与提供目标主体骨架的高级片段应按实际化学作用区分；用另一种字段或标签表达同一高级片段，不应改变许可。

库存身份判断沿用精确分子规则，不能为阻止目标盐型或保护形式绕过任务，而同时放松库存的立体化学/盐型匹配。目标相关形式属于任务范围判断，供应身份仍分别验证。

库存查询结果按精确身份及来源复用。任务判断在本任务内复用；若结论依赖该物质在路线中的作用，则不能仅以 SMILES 跨不同作用场景缓存。Editor 改变相关结构或用途时只重新判断受影响的候选，不重审整库。

## 6. 在现有系统中的位置

现有 `SequentialStrategyDirector._stock_membership()` 返回目录命中布尔值。部分开放叶重建直接以该布尔值判断是否保留待展开状态；`_branch_stock_closed()` 还会读取搜索引擎的根节点和叶闭合结果。这意味着只修改 prompt 或最终报告不足以改变搜索。

建议保留原始 stock oracle，增加一个集中处理任务终点许可的模块，位于“库存/来源查询完成”与“前体从待展开集合移除”之间。所有会终止、剪枝或恢复终点的入口调用同一模块，包括 Host/MCTS、外部搜索适配、Editor 修复后的叶集合重建和最终路线组合。

不要把任务拒绝返回成 `stock_membership=False`：这样会再次混淆库存与任务评价。也不要将整个任务许可写成全局分子属性，同一个分子在其他目标或任务中可能完全合理。

`material_boundary.py` 目前负责材料来源核查请求，不授予库存闭合；这与“已命中分子是否适合作为本任务起点”不同，不应直接改写它的含义来兼任新职责。

提示词插入位置：目标/任务说明之后、当前路线状态之前，作为同一份可插拔约束模块。Strategy 据此规划研究范围；Builder 接收规则及当前候选需要继续拆解的具体原因；语义判断可复用现有审阅调用中已有的上下文，但必须在候选获准停止之前完成，不能依赖搜索结束后才运行的整体 Critic。

## 7. 展示、成本与验收

网页保留两个可解释的事实：例如“目录命中 · 本任务可作起点”或“目录命中 · 仍需拆解”。未查询与未命中分别显示。任务范围不适配不能冒充化学 reject。

运行时不对几千万个分子调用模型。明确结构和通用试剂直接判断；只对实际遇到的模糊终点进行批量、缓存的语义判断。新增消耗来自这些判断，不能预先声称为零；每轮记录实际新增调用和 token，以便比较是否值得。

第一轮可用同一个匹伐他汀目标做两个范围对照：完整路线研究、允许现有喹啉醛的侧链连接研究。两轮使用相同原始库存，应得到不同的终点许可。再核查：CBr₄ 始终按通用试剂处理，目标及末期形式不会规避全路线要求，给定起始物确实连入目标，Editor/剪枝后判断一致，网页不把“继续拆解”显示为库存缺失。
